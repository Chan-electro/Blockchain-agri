ABSTRACT
================================================================================

AgriChain is a comprehensive blockchain-based supply chain tracking system 
designed specifically for agricultural products. The system provides complete 
transparency and traceability from farm to retail by leveraging Ethereum 
blockchain technology combined with a traditional database infrastructure. 

The platform implements multi-stakeholder pricing transparency, allowing 
consumers to view the complete price breakdown across all stages: Farmer → 
Processor → Logistics → Retailer. All transactions are recorded on an 
immutable ledger ensuring data integrity, while maintaining fast query 
performance through an off-chain SQLite database.

Key features include role-based dashboards, QR code scanning for product 
verification, real-time price breakdown visualization, and complete audit 
trails for all price additions and status changes.


1. INTRODUCTION
================================================================================

1.1 Background and Motivation

The agricultural supply chain is characterized by multiple intermediaries, 
complex pricing structures, and limited transparency. Consumers often lack 
information about where their food comes from and why prices are set at 
certain levels. Traditional supply chain systems suffer from:

- Lack of transparency in pricing
- Difficulty in verifying product authenticity
- Complex audit trails that are easily manipulated
- Poor traceability of agricultural products
- Information asymmetry between stakeholders

Blockchain technology offers a solution by providing an immutable, distributed 
ledger that records all transactions transparently. AgriChain leverages this 
technology to address these challenges.

1.2 Project Objectives

The primary objectives of the AgriChain project are:

1. Establish complete transparency in agricultural supply chains
2. Enable multi-stakeholder pricing with clear breakdowns
3. Provide immutable record-keeping using blockchain technology
4. Create user-friendly interfaces for all stakeholders
5. Ensure fast query performance through hybrid architecture
6. Enable easy product verification via QR codes
7. Build a scalable system that can handle real-world usage


2. SYSTEM ARCHITECTURE
================================================================================

2.1 Hybrid Architecture Design

AgriChain operates on a Hybrid Architecture that combines the best of 
blockchain and traditional web technologies:

┌─────────────────────────────────────────────────────┐
│         Frontend (React + TypeScript)               │
│  Farmer | Processor | Logistics | Retailer | Consumer
└────────────────────┬────────────────────────────────┘
                     │ REST API (HTTP)
        ┌────────────▼──────────────┐
        │  Backend (Express + SQLite) │
        │  - API Routes              │
        │  - Event Listeners         │
        │  - Database Sync           │
        └────────────┬────────────────┘
                     │ Ethers.js (Web3)
        ┌────────────▼────────────────┐
        │  Smart Contract (Solidity)  │
        │  AgriChain.sol             │
        │  Hardhat Network           │
        └─────────────────────────────┘

2.2 Component Description

Frontend Layer:
- Responsive web interface built with React 19.1.0 and TypeScript
- Role-based dashboards for different stakeholders
- QR code generation and scanning capabilities
- Real-time price breakdown visualization
- Modern UI with Tailwind CSS and Framer Motion animations

Backend Layer:
- Node.js/Express server (v5.1.0) acting as API gateway
- Manages blockchain transactions on behalf of users
- Listens for blockchain events and syncs with database
- Provides RESTful API endpoints for frontend
- Handles business logic and validation

Blockchain Layer:
- Solidity smart contract (v0.8.28) deployed on Ethereum-compatible network
- Hardhat local development network
- Stores critical data: ownership, pricing, status transitions
- Emits events for all state changes
- Provides single source of truth for supply chain data

Database Layer:
- SQLite database for off-chain caching
- Stores replicated blockchain data for fast querying
- Enables complex queries that would be expensive on-chain
- Maintains eventual consistency with blockchain

2.3 Why Hybrid Architecture?

The hybrid approach provides several advantages:

Security & Trust: Blockchain ensures data immutability and transparency
Speed & Usability: Database provides fast queries without blockchain overhead
Scalability: Complex queries hit SQL database, not blockchain node
User Experience: Users don't need crypto wallets or knowledge
Cost Efficiency: Reduces gas costs by minimizing on-chain operations


3. BLOCKCHAIN IMPLEMENTATION
================================================================================

3.1 Smart Contract Design

Contract Name: AgriChain.sol
Solidity Version: ^0.8.28
License: MIT

The smart contract implements the core business logic for the supply chain:

3.1.1 Data Structures

Batch Struct:
- id: Unique identifier for the batch
- farmer: Ethereum address of the farmer who created it
- crop: Type of agricultural product (e.g., "Basmati Rice")
- weight: Quantity in kilograms (stored as string)
- location: Origin location (e.g., "Punjab, India")
- createdAt: UNIX timestamp of creation
- status: Current lifecycle status (CREATED, PROCESSED, IN_TRANSIT, RETAIL, SOLD)
- totalPrice: Cumulative price across all stakeholders
- priceBreakdown: Array of PriceComponent structs

PriceComponent Struct:
- stakeholder: Ethereum address of the stakeholder
- role: Stakeholder type (FARMER, PROCESSOR, LOGISTICS, RETAILER)
- amount: Price contribution in INR (stored as uint256)
- description: Human-readable description (e.g., "Base Price", "Processing Fee")
- timestamp: UNIX timestamp when added

3.1.2 Core Functions

createBatch(crop, weight, location, basePrice):
- Creates a new batch with farmer's base price
- Initializes status as "CREATED"
- Adds first price component for farmer
- Emits BatchCreated event
- Returns: Transaction receipt with batch ID

addProcessingDetails(batchId, processingFee, description):
- Adds processor's fee to the batch
- Updates status to "PROCESSED"
- Appends price component to breakdown
- Emits PriceUpdated and StatusUpdated events
- Requires: Valid batch ID

updateLogistics(batchId, transportFee, description):
- Adds logistics provider's transportation fee
- Updates status to "IN_TRANSIT"
- Appends price component to breakdown
- Emits PriceUpdated and StatusUpdated events
- Requires: Valid batch ID

retailerReceive(batchId, markup, description):
- Adds retailer's markup to the batch
- Updates status to "RETAIL"
- Appends price component to breakdown
- Emits PriceUpdated and StatusUpdated events
- Requires: Valid batch ID

getBatchDetails(batchId):
- View function to retrieve complete batch information
- Returns all fields including full price breakdown array
- No gas cost (read-only operation)

3.1.3 Events

BatchCreated(id, farmer, basePrice):
- Emitted when a new batch is created
- Used by backend to sync database

PriceUpdated(id, stakeholder, role, amount, newTotal):
- Emitted when any stakeholder adds their price
- Tracks who added what amount and when

StatusUpdated(id, newStatus):
- Emitted when batch status changes
- Tracks supply chain progression

4.2.2 Blockchain.js
Handles all blockchain interactions:

Provider Setup:
- JsonRpcProvider connected to Hardhat network
- Uses first account as signer for development
- Supports custom private key via environment variable

Contract Initialization:
- Reads contract ABI from compiled artifacts
- Instantiates contract instance with signer
- Validates contract address from environment

Contract Interaction Methods:
- createBatch: Submits batch creation transaction
- addProcessing: Adds processing fee and updates status
- updateLogistics: Adds transport fee and updates status
- retailerReceive: Adds retail markup and updates status
- getBatchDetails: Retrieves complete batch information
- getBatchCount: Gets total number of batches

Event Parsing:
- Parses transaction receipts to extract event data
- Specifically extracts batch ID from BatchCreated event
- Returns structured data to API layer

4.2.3 Database Management

Database: SQLite 3
ORM: Native sqlite3 package v5.1.7
File: backend/database/agrichain.db

Schema Design:

Table: batches
- id: INTEGER PRIMARY KEY
- farmer_address: TEXT NOT NULL
- crop: TEXT NOT NULL
- weight: TEXT NOT NULL
- location: TEXT NOT NULL
- status: TEXT NOT NULL
- total_price: INTEGER NOT NULL
- created_at: INTEGER NOT NULL (UNIX timestamp)
- updated_at: INTEGER NOT NULL (UNIX timestamp)

Table: price_components
- id: INTEGER PRIMARY KEY AUTOINCREMENT
- batch_id: INTEGER NOT NULL (Foreign Key)
- stakeholder_address: TEXT NOT NULL
- role: TEXT NOT NULL (FARMER, PROCESSOR, LOGISTICS, RETAILER)
- amount: INTEGER NOT NULL
- description: TEXT
- timestamp: INTEGER NOT NULL (UNIX timestamp)

Indexes:
- idx_batches_farmer: Index on farmer_address for fast lookup
- idx_batches_status: Index on status for filtering
- idx_price_components_batch: Index on batch_id for joins

6. SYSTEM WORKFLOW AND USE CASES
================================================================================

6.1 Complete Workflow Example

Step 1: Farmer Creates Batch
- Farmer logs into Farmer Dashboard
- Fills form: Crop="Basmati Rice", Weight="500kg", Location="Punjab, India", 
  Base Price=₹100
- Clicks "Create Batch"
- Frontend sends POST /api/batch/create to backend
- Backend calls blockchain.createBatch()
- Smart contract creates batch with ID=1, status="CREATED"
- BlockchainCreated event emitted
- Database syncs: Insert into batches and price_components tables
- Frontend displays success with Batch ID
Result: Batch created with base price ₹100

Step 2: Processor Adds Processing Fee
- Processor views available batches in Processor Dashboard
- Selects Batch ID=1
- Adds: Quality Notes="Grade A quality", Processing Fee=₹20
- Clicks "Mark as Processed"
- Frontend sends POST /api/batch/update (type="processing")
- Backend calls blockchain.addProcessing(1, 20, "Grade A quality")
- Smart contract updates: total_price=₹120, status="PROCESSED"
- PriceUpdated and StatusUpdated events emitted
- Database syncs: Update batches.total_price and insert price_component
Result: Total price = ₹120 (100 + 20)

Step 3: Logistics Adds Transport Fee
- Logistics provider views batches in Logistics Dashboard
- Selects processed Batch ID=1
- Adds: Route="Farm to Processing Center", Transport Fee=₹10
- Clicks "Add to Transport"
- Frontend sends POST /api/batch/update (type="logistics")
- Backend calls blockchain.updateLogistics(1, 10, "Farm to Processing Center")
- Smart contract updates: total_price=₹130, status="IN_TRANSIT"
- Events emitted and database synced
Result: Total price = ₹130 (100 + 20 + 10)

Step 4: Retailer Adds Markup
- Retailer views in-transit batches in Retailer Dashboard
- Selects Batch ID=1
- Adds: Retail Markup=₹50
- Clicks "Receive to Store"
- Frontend sends POST /api/batch/update (type="retailer")
- Backend calls blockchain.retailerReceive(1, 50, "Retail Markup")
- Smart contract updates: total_price=₹180, status="RETAIL"
- QR code generated for batch
Result: Total price = ₹180 (100 + 20 + 10 + 50)

Step 5: Consumer Scans QR Code
- Consumer navigates to Consumer Scan page
- Scans QR code or enters Batch ID=1
- Frontend fetches GET /api/batch/1
- Backend queries database and/or blockchain
- Returns complete batch details with price breakdown
- Consumer sees transparent breakdown:
  * Farmer: ₹100 (55.6%)
  * Processor: ₹20 (11.1%)
  * Logistics: ₹10 (5.6%)
  * Retailer: ₹50 (27.8%)
  * Total: ₹180
Result: Complete transparency for consumer

6.2 Data Flow

Frontend → Backend (REST API):
- HTTP requests with JSON payloads

Backend → Blockchain (Ethers.js):
- Function calls via contract instance

- BatchCreated, PriceUpdated, StatusUpdated events
- Backend listens and syncs database
- Ensures eventual consistency

Backend → Database (SQL):
- INSERT on batch creation and price additions
- UPDATE on status changes
- SELECT for queries and reporting
